# Dynamic Notifications Plan

## Goal
Replace static scheduled notifications in `app/App.js` (`scheduleNotifications()`)
with server-sent push notifications whose body is generated by Haiku from live DynamoDB data.

## Why Server-Side
Expo's local `scheduleNotificationAsync` bakes content at schedule time — can't pull live data at delivery.
Need server-side push so content is generated fresh at send time.

## Full Data Flow
```
User opens app
  └── getDevicePushTokenAsync() → raw APNs token
        └── POST /register-token
              └── Lambda (lambda/register_token.py) → DynamoDB Stories table
                    └── { date: "_tokens", storyId: "<token>" }

GitHub Actions (7am / 12pm / 6pm / 10pm ET)
  └── notify job → scraper/notify.py
        ├── query DynamoDB date=TODAY → sort by sourceCount → top 3 mergedTitles
        ├── Claude Haiku (max_tokens=80) → 1 sentence
        ├── query DynamoDB date="_tokens" → all device tokens
        └── APNs HTTP/2 POST per token → iPhone notification
```

## Local Development

### Test without APNs credentials
```bash
cd scraper
# Uses existing .env (AWS + Anthropic keys already present)
python notify.py --dry-run
```
`--dry-run` prints the Haiku-generated sentence and skips the APNs send.

### Test with real APNs (physical device required — simulator won't work)
Add to `scraper/.env`:
```
APNS_KEY_ID=XXXXXXXXXX
APNS_TEAM_ID=XXXXXXXXXX
APNS_BUNDLE_ID=com.you.newsbites
APNS_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----"
APNS_SANDBOX=true
```
Then: `python notify.py`

### Plant a test token manually (skips Lambda)
```python
import boto3
table = boto3.resource("dynamodb", region_name="us-east-1").Table("Stories")
table.put_item(Item={
    "date": "_tokens",
    "storyId": "YOUR_REAL_DEVICE_TOKEN",
    "registeredAt": "2026-05-23T00:00:00Z",
})
```

## DynamoDB Token Storage

Device tokens are stored in the **existing** `Stories` table using a sentinel partition key:

```
date:    "_tokens"         ← never collides with real date strings (YYYY-MM-DD)
storyId: "<apns_token>"   ← raw APNs hex token as sort key
registeredAt: "..."
```

`_delete_stale()` in `dynamo.py` is safe — it only removes storyIds present in the
current cluster set, which never includes APNs token strings.

---

## Key Decisions
- Use only `mergedTitle` (not `mergedSummary`) for the Haiku prompt — minimises token cost
- Native APNs over Expo Push — existing Apple Developer account, no new service onboarding
- Tokens stored in existing `Stories` table under `date="_tokens"` sentinel — no new table needed
- `APNS_KEY` passed as env var (full `.p8` contents) — no file management at runtime
- JWT generated fresh each run — no rotation logic needed since `notify.py` is short-lived
- `notify` job uses its own cron triggers — `if:` condition gates it from the 15-min scrape crons
